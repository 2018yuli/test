# Cranelift

# Cranelift

A [Bytecode Alliance](https://bytecodealliance.org/) project

Bytecode Alliance 的一个项目

Cranelift is a *fast*, *secure*, *relatively simple* and *innovative* compiler backend. It takes an [intermediate representation](https://github.com/bytecodealliance/wasmtime/blob/main/cranelift/docs/ir.md) of a program generated by some frontend and compiles it to executable machine code. Cranelift is meant to be used as a library within an "embedder". It is in successful use by the [Wasmtime](https://github.com/bytecodealliance/wasmtime) WebAssembly virtual machine, for just-in-time (JIT) and ahead-of-time (AOT) compilation, and also as an [experimental backend](https://github.com/bjorn3/rustc_codegen_cranelift) for the [Rust](https://www.rust-lang.org/) compiler. Its most common use is as a WebAssembly compiler, but it is fully general and usable for most code-generation needs. Cranelift itself is written in Rust.

Cranelift 是一个 *快速*、*安全*、*相对简单*且*具有创新性*的编译器后端。它接收由某个前端生成的程序 [中间表示](https://github.com/bytecodealliance/wasmtime/blob/main/cranelift/docs/ir.md)，并将其编译为可执行机器码。Cranelift 旨在作为一个库在“embedder”中使用。它已在 [Wasmtime](https://github.com/bytecodealliance/wasmtime) WebAssembly 虚拟机中成功用于即时（JIT）和提前（AOT）编译，也作为 [Rust](https://www.rust-lang.org/) 编译器的一个 [实验性后端](https://github.com/bjorn3/rustc_codegen_cranelift)。它最常见的用途是作为 WebAssembly 编译器，但它是完全通用的，适用于大多数代码生成需求。Cranelift 本身是用 Rust 编写的。

Cranelift currently supports x86-64, aarch64 (ARM64), s390x (IBM Z), and riscv64 platforms. It is retargetable and contributions of further ISA support are welcome.

Cranelift 目前支持 x86-64、aarch64（ARM64）、s390x（IBM Z）和 riscv64 平台。它是可重定向的，欢迎为进一步的 ISA 支持做出贡献。

Cranelift is actively maintained and used in production to run sandboxed untrusted code with close-to-native performance. We continue to develop it to add feature support, improve performance, and further verify its correctness. We follow [Wasmtime](https://github.com/bytecodealliance/wasmtime)'s [release policy](https://docs.wasmtime.dev/stability-release.html) and [security policy](https://bytecodealliance.org/security).

Cranelift 目前正在积极维护中，并已在生产环境中用于以接近原生的性能运行沙箱中的不受信任代码。我们会持续开发它，以增加功能支持、提升性能，并进一步验证其正确性。我们遵循 [Wasmtime](https://github.com/bytecodealliance/wasmtime) 的 [发布策略](https://docs.wasmtime.dev/stability-release.html) 和 [安全策略](https://bytecodealliance.org/security)。

## Attributes

## 属性

- **Fast**: Cranelift is developed with the speed of the compiler itself in mind. We aim for Cranelift to be usable as a just-in-time (JIT) compiler. It has been [measured](https://arxiv.org/abs/2011.13127) to perform the code-generation process about an order of magnitude faster than an equivalent LLVM-based system.

- **快速**：Cranelift 在开发时充分考虑了编译器自身的速度。我们的目标是让 Cranelift 可用作即时（JIT）编译器。经[测量](https://arxiv.org/abs/2011.13127)，其代码生成过程的执行速度比等效的基于 LLVM 的系统快约一个数量级。

  Cranelift aims to generate fast-enough code, as well. While it does not have the aggressive optimization stance (or complexity) of larger compilers such as [LLVM](https://llvm.org/) or [gcc](https://gcc.gnu.org/), its output is often not too far off: the [same paper](https://arxiv.org/abs/2011.13127) showed Cranelift generating code that ran ~2% slower than V8 (TurboFan) and ~14% slower than an LLVM-based system.

Cranelift 也旨在生成足够快的代码。虽然它不像 [LLVM](https://llvm.org/) 或 [gcc](https://gcc.gnu.org/) 等大型编译器那样采取激进的优化立场（也没有其复杂性），但其输出通常相差不远：[同一篇论文](https://arxiv.org/abs/2011.13127)显示，Cranelift 生成的代码运行速度比 V8（TurboFan）慢约 2%，比基于 LLVM 的系统慢约 14%。

- **Secure**: Cranelift has a strong focus on correctness and verification. In addition to developing the compiler itself in a memory-safe language (Rust), we continually work to test and verify the compiler in new ways with [fuzzing](https://bytecodealliance.org/articles/1-year-update#improving-testing-with-fuzzing), [symbolic translation validation](https://cfallin.org/blog/2021/03/15/cranelift-isel-3/) of some stages, correctness proofs for critical pieces where appropriate, and more recently, static [formal verification](https://www.cs.cornell.edu/~avh/veri-isle-preprint.pdf) as well. We have designed the compiler with abstractions to prevent bugs and enforce invariants wherever possible. We consciously navigate complexity tradeoffs and choose to avoid some riskier and more error-prone optimization techniques. For example, unlike most optimizing compilers, our IR does not have undefined behavior, by design. Finally, we keep up to date with mitigation techniques, both for side-channel attacks like [Spectre](https://en.wikipedia.org/wiki/Spectre_(security_vulnerability)), and for general defense-in-depth with [hardware CFI features](https://github.com/bytecodealliance/rfcs/blob/main/accepted/cfi-improvements-with-pauth-and-bti.md) and other hardening.

- **安全**：Cranelift 非常重视正确性和验证。除了使用内存安全语言（Rust）开发编译器本身之外，我们还持续以新的方式测试和验证编译器，包括[模糊测试](https://bytecodealliance.org/articles/1-year-update#improving-testing-with-fuzzing)、对某些阶段进行[符号化翻译验证](https://cfallin.org/blog/2021/03/15/cranelift-isel-3/)、在适当情况下为关键部分提供正确性证明，以及最近还采用静态[形式化验证](https://www.cs.cornell.edu/~avh/veri-isle-preprint.pdf)。我们在设计编译器时使用抽象来尽可能防止 bug 并强制执行不变量。我们有意识地权衡复杂性取舍，并选择避免一些风险更高且更容易出错的优化技术。例如，与大多数优化编译器不同，我们的 IR 在设计上没有未定义行为。最后，我们持续跟进缓解技术，既包括针对 [Spectre](https://en.wikipedia.org/wiki/Spectre_(security_vulnerability)) 等侧信道攻击的缓解，也包括使用[硬件 CFI 功能](https://github.com/bytecodealliance/rfcs/blob/main/accepted/cfi-improvements-with-pauth-and-bti.md)和其他加固手段进行通用的纵深防御。

  Cranelift is also, like browser JIT engines' compilers but unlike LLVM or gcc, specifically hardened against malicious compiler input: it is written to guard against pathological runtimes, for example by avoiding input-length-bounded recursion, and quadratic or higher algorithmic complexity wherever possible. It is not a linear-time single-pass compiler, but it is still suitable for compiling untrusted code (for example, Wasm modules). We fuzz while monitoring for out-of-memory and timeout conditions in compilation to verify this.

Cranelift 还像浏览器 JIT 引擎的编译器一样，但不同于 LLVM 或 gcc，专门针对恶意编译器输入进行了加固：其编写方式旨在防范病态运行时间，例如尽可能避免受输入长度限制的递归，以及二次或更高阶的算法复杂度。它不是线性时间的单遍编译器，但仍然适合编译不受信任的代码（例如 Wasm 模块）。我们在模糊测试时会监控编译过程中的内存耗尽和超时情况，以验证这一点。

  Cranelift follows the [Bytecode Alliance security policy](https://bytecodealliance.org/security). We have had two sandbox-escape-capable miscompilation CVEs since Cranelift development began in 2016. We welcome responsible disclosure of vulnerabilities and we follow best practices in disseminating notices and patches.

Cranelift 遵循 [Bytecode Alliance 安全策略](https://bytecodealliance.org/security)。自 2016 年 Cranelift 开始开发以来，我们曾有两个能够导致沙箱逃逸的误编译 CVE。我们欢迎负责任地披露漏洞，并遵循最佳实践来发布通知和补丁。

- **Relatively simple**: Cranelift is an optimizing compiler, but it aims to take a fresh look at which optimizations are necessary. We have explicitly avoided features -- such as advanced alias analysis or use of undefined behavior -- that have historically led to subtle miscompilations in other compilers. Cranelift consists of about 200 thousand lines of code; in contrast, e.g. LLVM consists of over 20 million lines of code, a hundred times larger. This difference also allows Cranelift to be relatively approachable to developers, researchers, auditors and others who wish to understand how it works.

- **相对简单**：Cranelift 是一个优化编译器，但它旨在重新审视哪些优化是必要的。我们明确避免了一些在历史上导致其他编译器出现微妙误编译的特性——例如高级别名分析或利用未定义行为。Cranelift 由大约 20 万行代码组成；相比之下，例如 LLVM 由超过 2000 万行代码组成，规模大了一百倍。这种差异也使 Cranelift 对希望了解其工作原理的开发者、研究人员、审计人员以及其他人来说相对更容易上手。

- **Innovative**: In order to compete as a viable alternative to larger compilers, and in order to maximize correctness and security in particular, Cranelift is open to innovative approaches, and aims to be an actively welcoming home to research collaborations. We are (to our knowledge) the first production compiler to use [e-graphs](https://github.com/bytecodealliance/rfcs/pull/27) to build a unified optimization framework. We have developed new fuzzing techniques, such as a [semantics-preserving fuzzing mutator](https://www.jacarte.me/assets/pdf/wasm_mutate.pdf) and a [symbolic translation validator](https://cfallin.org/blog/2021/03/15/cranelift-isel-3/) for our register allocator. We developed a [custom pattern-matching DSL](https://github.com/bytecodealliance/wasmtime/blob/main/cranelift/isle/docs/language-reference.md) for optimization rewrite rules and instruction lowering rules in order to ensure correctness and allow high-level integration with verification tools. We strongly leverage fuzzing with custom oracles, such as differential comparison of execution results or validation of invariants (in practice more similar to [property-based testing](https://en.wikipedia.org/wiki/Software_testing#Property_testing)) in order to efficiently find bugs and develop with high confidence. We actively collaborate with several academic groups to [formally verify](https://www.cs.cornell.edu/~avh/veri-isle-preprint.pdf) parts of the compiler.

- **创新**：为了作为大型编译器的可行替代方案参与竞争，并且尤其为了最大化正确性与安全性，Cranelift 对创新方法持开放态度，并致力于成为一个积极欢迎研究合作的家园。据我们所知，我们是第一个使用 [e-graphs](https://github.com/bytecodealliance/rfcs/pull/27) 来构建统一优化框架的生产级编译器。我们开发了新的模糊测试技术，例如用于我们寄存器分配器的[保持语义的模糊测试变异器](https://www.jacarte.me/assets/pdf/wasm_mutate.pdf)和[符号化翻译验证器](https://cfallin.org/blog/2021/03/15/cranelift-isel-3/)。我们开发了一种用于优化重写规则和指令降低规则的[自定义模式匹配 DSL](https://github.com/bytecodealliance/wasmtime/blob/main/cranelift/isle/docs/language-reference.md)，以确保正确性并允许与验证工具进行高层次集成。我们强烈利用带有自定义预言机的模糊测试，例如对执行结果进行差分比较或验证不变量（在实践中更类似于[基于属性的测试](https://en.wikipedia.org/wiki/Software_testing#Property_testing)），以便高效地发现 bug 并以高信心进行开发。我们积极与多个学术团队合作，对编译器的部分内容进行[形式化验证](https://www.cs.cornell.edu/~avh/veri-isle-preprint.pdf)。

## Documentation

## 文档

Cranelift has [general documentation](https://github.com/bytecodealliance/wasmtime/tree/main/cranelift/docs/) describing aspects of its design, such as its [intermediate representation](https://github.com/bytecodealliance/wasmtime/blob/main/cranelift/docs/ir.md), CLIF. Many of the [Wasmtime documents](https://docs.wasmtime.dev/) are also applicable: Cranelift is developed in-tree in Wasmtime and generally follows its development, testing and release processes, for example.

Cranelift 有[通用文档](https://github.com/bytecodealliance/wasmtime/tree/main/cranelift/docs/)描述其设计的各个方面，例如其中间表示 [CLIF](https://github.com/bytecodealliance/wasmtime/blob/main/cranelift/docs/ir.md)。许多 [Wasmtime 文档](https://docs.wasmtime.dev/)也同样适用：例如，Cranelift 在 Wasmtime 树内开发，并且通常遵循 Wasmtime 的开发、测试和发布流程。

For users of Cranelift, the API documentation for the main crate [`cranelift-codegen`](https://docs.rs/cranelift-codegen) and its auxiliary helpers for IR producers and Wasm-centric embedders, [`cranelift-frontend`](https://docs.rs/cranelift-frontend) and [`cranelift-wasm`](https://docs.rs/cranelift-wasm) respectively, may be useful to reference. Developers of Cranelift backends will find the above API references useful, as well as the [ISLE DSL reference](https://github.com/bytecodealliance/wasmtime/blob/main/cranelift/isle/docs/language-reference.md).

对于 Cranelift 用户，主 crate [`cranelift-codegen`](https://docs.rs/cranelift-codegen) 的 API 文档，以及面向 IR 生成者和以 Wasm 为中心的嵌入者的辅助工具 [`cranelift-frontend`](https://docs.rs/cranelift-frontend) 和 [`cranelift-wasm`](https://docs.rs/cranelift-wasm) 的 API 文档，可能会很有参考价值。Cranelift 后端的开发者也会发现上述 API 参考很有用，此外还有 [ISLE DSL 参考](https://github.com/bytecodealliance/wasmtime/blob/main/cranelift/isle/docs/language-reference.md)。

Finally, please do feel free to stop by our [Zulip chat instance](https://bytecodealliance.zulipchat.com/) and ask questions -- we are happy to help!

最后，也欢迎随时到我们的 [Zulip 聊天实例](https://bytecodealliance.zulipchat.com/) 提问——我们很乐意提供帮助！

## Contributing

## 贡献

We welcome anyone who wishes to help develop Cranelift to join our community and talk with us! The [contributing](https://bytecodealliance.github.io/wasmtime/contributing.html) documentation page from Wasmtime offers many tips that apply equally to Cranelift, as a project hosted in the same repository with a largely overlapping community. In particular, under the [mentoring](https://docs.wasmtime.dev/contributing.html#mentoring) heading on that documentation page, you can find links to "easy first issues". Finally, we hold a [weekly meeting](https://github.com/bytecodealliance/meetings/tree/main/cranelift) in which we discuss current development topics and ideas and usually make a round of status updates. Joining this meeting may be a good way to learn more about what we're working on (you don't have to speak!) and anyone who wishes may join.

我们欢迎任何希望帮助开发 Cranelift 的人加入我们的社区并与我们交流！Wasmtime 的 [贡献](https://bytecodealliance.github.io/wasmtime/contributing.html) 文档页面提供了许多同样适用于 Cranelift 的建议，因为 Cranelift 是托管在同一仓库中的项目，并且社区在很大程度上重叠。特别是，在该文档页面的 [mentoring](https://docs.wasmtime.dev/contributing.html#mentoring) 标题下，你可以找到指向“easy first issues”的链接。最后，我们会举行一个[每周会议](https://github.com/bytecodealliance/meetings/tree/main/cranelift)，在会上讨论当前的开发主题和想法，并通常进行一轮状态更新。加入这个会议可能是了解我们正在做什么的好方式（你不必发言！），任何愿意的人都可以参加。
